## Use case: launch-runbook

**Trigger**: any product release, site launch, or announcement. Invoked as part of social-post or standalone.

## T-1 day (prep — crew runs, cmo verifies)
- [ ] Claims verified (research-analyst): every public claim has a link; no standard/hype overclaims
- [ ] Creatives rendered (builder): X card + LinkedIn slides, house palette, thumbnail-readable
- [ ] Landing surface live (qa-release smoke): the thing being announced resolves and works
- [ ] Measurement baseline captured (data-analyst): installs/sessions/stars snapshot BEFORE launch
- [ ] Reviewer SHIP verdict on all drafts
- [ ] Timing chosen (platform rules from social-post skill; default X Tue/Wed 7:30-8:30 PM IST)

## T-0 (publish hour — Principal executes, crew supports)
- [ ] X: main post → first reply (link) → second reply (how-to-test/caveats)
- [ ] LinkedIn: carousel + link in first comment
- [ ] First hour: Principal replies to comments; CMO drafts reply support on request
- [ ] Crew logs: post URLs, exact timestamps, initial impressions

## T+1 / T+7 (follow-up — data-analyst + social-listener)
- [ ] Delta report vs baseline: installs, sessions, stars, clones (the scoreboard, not vanity impressions)
- [ ] Social-listener: replies/mentions/threads spawned — answerable follow-ups routed
- [ ] What worked (labeled Inference) — feeds the next launch's timing/format choices

## Output contract
- `memory/briefs/<YYYYMMDD>-launch-<topic>-<phase>.md` per phase (prep / publish / followup)
- The T-1 checklist must be all-green (or waived items named by the Principal) before T-0 proceeds

## Quality bar
- baseline captured before publishing · claims linked · reviewer passed · scoreboard deltas reported at T+1/T+7 · nothing published by any agent
