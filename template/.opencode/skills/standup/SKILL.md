## Use case: standup

**Trigger**: `standup` from the principal, or the scheduled 09:00 IST beat (re-armed 2026-09-20 after the Sep-4 wedge fixes — watch the first clean runs; if it misbehaves again, fall back to manual). This is the cmo's own playbook — the order is fixed, judgment applies per step. The day-folder mechanics (folder contract, scheduling rule, carry-forward) live in the `daily-checks` skill; this skill is the beat that runs inside it.

## The order (and why this order)

Grounding in goals, Linear milestones, and studio products is mandatory.
2. **Fleet census first, then the external sweep.** Two parts, in this order:

## Reading rules (from the fleet ontology — binding)

Read `mcp-playbook/FLEET-ONTOLOGY.md` + `skills/classify-traffic.md` + `skills/metrics-definitions.md` before interpreting any number. The short form:

1. **An MCP is not a SaaS product.** Local binary, no central control, fix forward only. There is no fleet DAU and no fleet-wide delivery rate. Comparing Google Analytics query volume to a bioRxiv paper search is a category error.
2. **Classify first.** N1-N5 (scanners, ephemeral infra, directory crawlers, fuzzers, our tests) are removed before any read. U1-U4 are humans, human-driven agents, scheduled jobs, pipelines.
3. **Boots are harness mechanics.** Every harness boots and lists tools for every configured MCP on start. Boots measure install-base footprint and client mix. Boots-to-calls ratios are meaningless.
4. **Zero rows is often ground truth.** A GSC query with no clicks, a search with no matching paper — valid answers, never delivery failures.
5. **Read each server against its own ICP and rhythm.** Episodic servers are silent most days by design. Silence is a reading, not a defect. Diagnostics are per-server: execution success, payload utility, code-fixable defect rate.
6. **macos-companion is boots-only by design** (privacy-deliberate: Mail, Calendar, Notes, clipboard). Its calls, rows and intent cells are `n/a`, never `0`, and low invocation frequency is expected.
7. **Whittle is wired to a separate PostHog instance** and is not missing from this one. Same for the two retired Workers listed in the roster config.

Never print a fleet-wide rate, a fleet DAU, a boots-to-calls ratio, or a "silent server" count as a health verdict. Note gaps in one line, keep moving — an instrumentation gap is not a blocker.

## Rules

- The sweep is unconditional; every other step is conditional on what today's agenda and the sweep surface.
- A blocked source is a finding, not a failure to hide — it prints in the sweep.
- **A zero is only a zero when the server emits that event.** The capability map in the census artifact decides: `n/a` for a signal the server never sends, `0` for a signal it sends but did not send today. Never read silence as churn or as health.
- No step publishes anything. Drafts and tickets only; Surendran posts and decides.
- If the sweep cannot run (auth failure, network), the standup IS the failure report: what broke, exact error, what he needs to do. Never silence.
- End the run with a one-line git commit and any lessons appended to `memory/learnings.md`.
