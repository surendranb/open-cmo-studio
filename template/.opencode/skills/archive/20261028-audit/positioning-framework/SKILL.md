# Positioning Framework

Methodology for defining, stress-testing, and sharpening B2B tech and AI product positioning using April Dunford's 5-component framework (*Obviously Awesome*).

## The 5 Components of Product Positioning

```
1. Competitive Alternatives
   (What would customers use or do if this product did not exist?)
     ↓
2. Unique Attributes & Capabilities
   (What features or architectural capabilities do we have that alternatives lack?)
     ↓
3. Value Delivered & Proof Points
   (What tangible business value do those unique capabilities unlock, backed by evidence?)
     ↓
4. Target Customer Segment
   (Who cares desperately about that value? Firmographics, tech maturity, pain triggers)
     ↓
5. Market Category Context
   (What category makes the value obvious to the customer without 10 minutes of explanation?)
```

## Step-by-Step Positioning Protocol

### Step 1: Identify Real Competitive Alternatives
*Mistake to avoid:* Do not compare against your dream competitors only. Compare against what the customer is actually using today.
- Direct software alternatives (named tools).
- Status quo / Inertia (spreadsheets, manual glue scripts, in-house DIY builds).
- "Do nothing / hire another junior person".

### Step 2: Isolate Genuine Unique Attributes
List features and architectural choices that are objectively unique:
- *Test:* Can a competitor copy-paste this claim on their website tomorrow? If yes, it is not a unique attribute.
- Group into: Data/Engine moats, Workflow/UX advantages, Deployment/Privacy models (e.g. Local-first vs Cloud SaaS), Cost/Licensing advantages.

### Step 3: Translate Attributes into Provable Value
Never stop at the feature. Map feature → benefit → business outcome:
- Formula: `[Unique Feature]` enables `[Operational Capability]`, which produces `[Quantifiable Business Outcome]`.
- Proof required: Case study metric, customer quote, benchmark latency/cost reduction, or live telemetry.

### Step 4: Define the "Desperate" Target Segment
Who gets 10x value from this specific outcome?
- Must define both who it is FOR and who it is NOT FOR.
- Triggers: "When a team reaches 50 engineers...", "When regulatory compliance requires data never leave macOS...", "When monthly LLM API bills cross $10k...".

### Step 5: Choose the Category Context
Categories set instant customer expectations on price, competitors, and features:
- **Head to Head**: Winning an existing category (e.g. "A faster, local-first CRM").
- **Big Fish, Small Pond (Sub-segment)**: Dominating a specialized niche (e.g. "CRM exclusively for open-source dev tool companies").
- **Category Creation**: Defining a fundamentally new context (e.g. "Autonomous CMO Operating System"). High educational cost; only choose when existing categories actively distort customer perception.

## Output Templates

### The Canonical Positioning Statement
```markdown
For **[Target Customer Segment]**
Who **[Specific Pain or Operational Trigger]**,
**[Product Name]** is a **[Market Category]**
That **[Primary Unique Value / Core Benefit]**.
Unlike **[Primary Competitive Alternatives]**,
**[Product Name]** **[Primary Unique Differentiator & Moat]**.
```

### Elevator Pitch Matrix
- **10-Second Pitch (The Hook):** One punchy sentence declaring category + distinct value.
- **30-Second Pitch (The Conversation):** Problem context + unique capability + proven outcome.
- **60-Second Pitch (The Teardown):** Full problem teardown + architecture differentiation + social proof + call to action.

### Messaging Pillars Hierarchy
Every product should have exactly 3 core messaging pillars:
- **Pillar 1:** The Core Efficiency / Speed / Cost Moat (Operational ROI)
- **Pillar 2:** The Experience / Workflow Moat (Practitioner Delight)
- **Pillar 3:** The Trust / Security / Architecture Moat (Enterprise Governance)
